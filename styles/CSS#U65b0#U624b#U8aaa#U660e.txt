《game-ui.css / CSS 外觀分拆新手指南》

一、這些檔案是做甚麼？
CSS 是遊戲的「外觀設計規則」，例如位置、大小、顏色、邊框、字體、按鈕樣式和動畫。它通常不負責決定角色有多少血、敵人受多少傷或何時過關；那些屬於 JavaScript 的工作。

原本所有外觀規則都擠在 styles/game-ui.css。現在把它分成多個小檔案，方便找內容。styles/game-ui.css 本身保留作「總入口」，只負責按順序載入以下分檔，不再放大量樣式。

二、分檔地圖（由上到下，載入次序很重要）

01-theme-layout.css
  用途：全局顏色變數、頁面基本設定、遊戲舞台、血量／能量顯示、角色與敵人的基本外觀。
  常見修改：整體配色、舞台大小、基本角色大小、血條樣式。

02-buttons-and-enemy-sprites.css
  用途：方向鍵、攻擊按鈕、暫停按鈕，以及敵人圖片素材／外觀狀態。
  常見修改：手機操作按鈕的外觀、按鈕圖片、敵人狀態圖片。

03-title-and-tutorial.css
  用途：首頁背景層、首頁開始／設定／教學／排行榜的點擊範圍，以及教學面板。
  常見修改：首頁按鈕位置、首頁圖層、教學畫面外觀。

04-character-animation-and-title.css
  用途：角色行走、跳躍、槍刺、盾擊、受傷等 CSS 動畫，以及首頁版面細節。
  常見修改：角色動作動畫的速度、部分首頁排版。

05-levels-and-camera.css
  用途：關卡提示、戰場寬度／鏡頭相關外觀規則。
  常見修改：關卡畫面及世界區域的顯示方式。鏡頭實際移動仍由 JavaScript 控制。

06-alignment-and-fixes.css
  用途：角色與敵人腳底對齊、角色圖片影格尺寸、敵人名字／血條，以及歷次修正。
  常見修改：角色站地高度、敵人大小、圖片位置。這裡有較多「修正覆蓋規則」，改之前要小心。

07-ultimate-effects.css
  用途：Q 大絕按鈕、蓄力金光、神聖槍爆環形衝擊波，以及大絕圖片影格的大小和位置。
  常見修改：大絕特效顏色、光圈大小、動畫速度、影格視覺比例。

三、如何讀懂 CSS 的基本語法？

例子：
.hero {
  width: 116px;
  height: 158px;
}

.hero 是「選擇器」，表示要改哪個元素；這裡是角色外框。
width 是寬度；height 是高度。
116px、158px 是像素數值。數字越大，元素通常越大。
大括號 { } 裡面是這個元素的外觀設定。

常見選擇器：
.hero             角色外框
#heroSprite       角色圖片（# 表示 HTML 元素的 id）
.gamebtn          遊戲操作按鈕
.hud              血量、能量、擊殺數等介面
.enemy            敵人外框
.overlay          暫停或結果等覆蓋畫面
.title-screen     首頁畫面

常見屬性：
width / height   寬度／高度
left / top       距離左邊／上邊的位置
bottom            距離底部的位置
color             文字顏色
background        背景顏色或背景圖片
border            邊框
font-size         文字大小
z-index           疊放順序；數字較大通常會顯示在較上層
position          定位方式；absolute 常用於把角色／按鈕放在指定位置
transform         位移、縮放或旋轉
animation         使用哪個動畫
transition        數值變化時的過渡效果
!important        強制提高這條規則的優先程度；不宜隨便加

四、為甚麼同一個角色會在不同檔案出現很多次？
這是 CSS 的「覆蓋」機制：同一個元素可以先有基本外觀，後面再加上新設計或修正。例如先設定 .hero 的大小，之後再針對 .hero.walking 設定行走動畫。後面的規則可能覆蓋前面的同一屬性。因此分檔時必須保持原本載入順序，不能隨便交換 01 至 07 的次序。

五、如何安全修改？
1. 先複製整個遊戲資料夾作備份。
2. 先找對應分檔，不要同時改多個檔案。
3. 一次只改一個數值，例如 width: 116px 改成 125px。
4. 儲存後重新整理遊戲，測試首頁、移動、攻擊、大絕及手機按鈕。
5. 如果畫面亂了，先把剛才改動還原；不要為了解決一個位置問題到處加 !important。

六、特別提醒
這次分拆目標是「讓外觀程式容易找到」，不是重做遊戲。各檔案的規則按原有先後順序切分，並由 game-ui.css 依序載入，盡量避免改變外觀結果。仍然要在瀏覽器實際測試；語法檢查不等於已確認畫面完全一致。
